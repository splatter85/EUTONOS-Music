# Delivery plan — smallest working system

Document ID: `EM-D009`  
Status: revised direction; implementation pending.

**M1 — standalone MVP:** EMF01 checks actual FL/agent/audio environment. EMF02 makes two compatible recordings and a sound palette. EMF03 chooses one playback backend. **EMF15 moves early:** one real AI prompt → editable FL Studio change → exported loop/sound through a small Visual Basic controller. EMF04 assembles a basic procedural recipe, DJ transitions and little state/genre/next-song app. EMF05 checks code and hears the result.

**M2 — expand only what is useful:** EMF06–EMF13 harden the asset library, state, app, procedural variation, DJ selection/history and more transition types. The first MVP does not need this entire framework.

**M3 — connect Mission Control afterward:** EMF14 uses the working standalone DJ interface. Start with explicit state requests; add any optional Mission Control activity mapping only after that works. EMF16 optional production jobs are not a prerequisite.

**M4 — broader acceptance:** EMF17–EMF19 review and qualify the assembled system. More genres, vocals, three-day variety, general DAW automation and broader distribution remain future work.

The [MVP acceptance](FIRST_PLAYABLE.md) is the first finish line. Original stage IDs remain stable; **EMF15 is deliberately scheduled before EMF04**. Do not mark any stage complete without actual evidence.
