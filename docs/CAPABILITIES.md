# Preliminary capabilities

Document ID: `EM-D003`  
Status: intended outcomes, 2026-11-03. These runtime capabilities are not yet available.

A capability describes something a person can get done. It may depend on several [features](FEATURES.md). This catalogue keeps the outcome visible while the campaign builds the pieces.

| Stable ID | Intended capability | Features involved | Acceptance example |
| --- | --- | --- | --- |
| EM-C001 | Listen to music that develops with a chosen state | EM-F001–F003 | Select Explore, hear it settle, request Drive, and hear a musically planned change. |
| EM-C002 | Hear different musical identities without leaving a mood | EM-F004–F007, F015 | Remain at moderate energy while distinct compatible recipes and recordings appear without immediate repeats. |
| EM-C003 | Move smoothly between recorded and generated music | EM-F002, F006–F008 | A rendered stem bundle hands its bass/harmonic role to a procedural passage and returns to a different recording. |
| EM-C004 | Control music from another application | EM-F001, F009–F010 | A test client sends revisioned intent, observes the pending plan, and receives the actual transition outcome. |
| EM-C005 | Produce library material with FL Studio | EM-F004, F011, F014 | A reviewed project produces aligned stems or an eligible instrument pack with metadata and a reproducible render recipe. |
| EM-C006 | Direct an assistant in ordinary musical language | EM-F011–F014 | “Keep the melody, reduce the hats, give the chords more space” becomes a bounded edit plan and an auditionable revision. |
| EM-C007 | Use local model production where appropriate | EM-F012–F013 | A configured adapter completes a background job, records model/version/settings, and submits an artifact for review. |
| EM-C008 | Add deliberate vocal performances | EM-F013–F014 | A phrase has reviewed pronunciation, pitch, timing and expression, plus usable boundaries for the intended arrangement. |
| EM-C009 | Revisit a musical moment | EM-F004, F015 | Restore the recorded asset versions, recipe version, seed, settings and relevant history for a saved vibe. |
| EM-C010 | Evaluate a long listening experience | EM-F005, F015–F016 | Examine coverage, repeats, state fit, resource growth and listening notes for a named long-run session. |
| EM-C011 | Add a new style without rewriting the engine | EM-F004, F007, F014 | A versioned recipe and approved palette express the style through the existing performer contract. |
| EM-C012 | Learn to improve the music | EM-F014, F016 | Use explicit listening criteria and controlled revisions to identify whether the issue is composition, sound, mix or transition behavior. |

## Available today

The repository provides a navigable design baseline, detailed educational guides, illustrative contracts, and a campaign suitable for implementation pickup. It provides no executable runtime capability listed above yet.

## Evidence rules

- Name the environment and content actually used in a demonstration.
- Track what was heard, measured, inferred, or left unverified.
- Do not extrapolate one successful seed to every recipe or genre.
- Do not confuse library reachability with a pleasant three-day musical journey.
- Keep a capability's accepted scope explicit when only a subset of its features is implemented.
